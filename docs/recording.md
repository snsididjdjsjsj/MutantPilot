# 逻辑帧录像

录像读的是游戏画完的画面，不包含别的窗口。编码按游戏逻辑帧排队，队列满了就等待，不丢帧。游戏帧号不连续或分辨率变了，这次录像失败。

搜索变慢时，墙上时间会比游戏时间长。从 0.3.97 起，每个视频帧都记了墙上时间戳。0.3.122 仍使用这条路径。scripts/warp_and_mux.py 用这个对应关系把环回录到的音效拉回游戏时间轴，再封进 MP4。这个脚本需要 numpy，在仓库根目录执行 pip install -r requirements.txt。环回录音是 Windows 程序 tools/LoopbackRec，走默认输出设备，不需要立体声混音。

0.3.95 的长录曾在读取后缓冲时持续增加内存，那一版不能用来做长录像。0.3.96 改成复用一张离屏纹理，并在内存涨过限额时停止。仓库里没有附带这些录像。

核对某一段成片：

```powershell
python scripts/verify_logic_video.py "某段.mp4" --ffprobe "ffprobe.exe"
```

它检查 60/1 FPS、帧数和游戏 tick 是否连续。加 `--hardware-decode` 时会再用 NVDEC 把帧解码一遍。脚本若写出报告，报告里包含解析后的本机路径，不要把报告提交进仓库。

画面连续和战斗无伤是两件分开的事。
